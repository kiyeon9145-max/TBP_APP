PLAYER DEVELOPMENT SYSTEM

PDS User Flow v0.1

유소년 야구 코치가 선수 등록부터 수업 기록, Skill Ladder, 영상 관리, 월간 리포트, 다음 목표 설정까지 실제 현장에서 사용하는 흐름을 정의한 문서입니다.

문서 유형 · User Flow대상 · Coach MVP버전 · 0.1

1. 문서 목적

요구사항 명세서에서 정의한 기능이 실제 코치의 업무 과정에서 어떤 순서로 사용되는지 명확히 한다. 이후 화면 명세서, Wireframe, DB ERD 설계의 기준 문서로 사용한다.

핵심 UX 원칙 · 모바일 우선 / 선수 1명 기록 30초 이내 / 중복 입력 최소화 / 행동 기반 기록 / AI 결과는 코치 승인 후 저장·발행

2. Main User Journey

선수 등록→클래스 배정→수업→관찰 기록→Skill·미디어→데이터 누적→월간 리포트→다음 목표↺

리포트 발행이 종료점이 아니다. 리포트의 다음 목표가 다음 달 수업의 현재 목표로 다시 연결되어야 한다.

3. 상세 User Flow

MVP에서 코치가 수행하는 13개의 핵심 업무 흐름이다.

01

최초 선수 등록

새로운 선수를 시스템에 등록하고 클래스·초기 Skill·현재 목표를 설정한다.

Dashboard→선수 등록→기본정보 입력→클래스 선택→초기 Skill 설정→현재 목표 설정→저장→Player Detail 생성
완료 조건 / 결과
Player + Class Membership + Initial Skill + Goal 생성. 초기 평가가 어려우면 '미평가' 허용.
02

수업 전

오늘 수업과 참여 선수를 확인하고 수업 세션을 시작한다.

로그인→Dashboard→오늘 수업 선택→참여 예정 선수 확인→출석/결석 확인→수업 시작
완료 조건 / 결과
Class Session 생성. 날짜·클래스·출결·진행 상태를 저장.
03

수업 중 빠른 기록

현장에서 선수별 관찰을 30초 이내로 기록한다.

수업 진행 화면→선수 선택→기술 선택→Skill 확인→시도/성공 입력→관찰 메모→사진·영상 추가(선택)→저장 & 다음 선수
완료 조건 / 결과
한 선수의 기록 완료 후 다음 선수로 빠르게 이동.
04

한 선수의 복수 관찰

한 수업에서 같은 선수에게 여러 기술 관찰 기록을 남긴다.

선수 선택→받기 기록→던지기 기록→치기 기록→필요 시 추가 Observation→저장
완료 조건 / 결과
한 선수+한 수업에 여러 Observation을 허용.
05

사진·영상 기록

미디어를 선수·날짜·수업·기술과 연결해 저장한다.

Class Log 또는 Player Detail→촬영/파일 선택→선수 연결→날짜/수업 연결→기술 선택→태그/메모→저장
완료 조건 / 결과
모든 Media는 최소 Player / Date / Skill을 가져야 함.
06

Skill Ladder 업데이트

관찰 근거를 보고 코치가 Skill 단계를 직접 변경한다.

Player Detail→Skill 선택→현재 단계 확인→최근 관찰 근거 확인→다음 단계 기준 확인→변경 승인→History 저장
완료 조건 / 결과
자동 승급 금지. 과거 Skill을 덮어쓰지 않고 변경 이력 보존.
07

수업 종료

누락 기록을 확인하고 수업을 종료한다.

수업 종료 선택→출석/기록 현황 확인→미작성 선수 확인→계속 기록 또는 일단 종료→Dashboard
완료 조건 / 결과
미작성 상태로 종료 가능. Dashboard에 미작성 업무 표시.
08

수업 후 기록 보완

수업 중 못 남긴 기록을 나중에 보완한다.

Dashboard→미작성 기록 선택→선수 선택→기록 작성 또는 음성메모 정리→AI 초안 확인(향후)→코치 확인→저장
완료 조건 / 결과
AI가 직접 저장하지 않고 코치 승인 후 저장.
09

Player Detail 확인

한 선수의 현재 상태와 성장 히스토리를 통합 조회한다.

Players→선수 선택→Overview→수업기록 / Skill / 영상 / Report 탭→현재 목표·최근 변화 확인
완료 조건 / 결과
선수 성장 프로필 역할.
10

월말 리포트 생성

한 달간 누적된 데이터를 리포트 작성 화면으로 불러온다.

Dashboard→Monthly Report→대상 월 선택→선수 선택→월간 데이터 불러오기→리포트 작성 시작
완료 조건 / 결과
수업 기록 + Skill 변화 + 성공/시도 + 미디어 + 이전 목표를 집계.
11

AI 리포트 초안

누적 기록만 근거로 부모용 리포트 초안을 생성한다.

월간 데이터 확인→AI 초안 생성→이번 달 발견→현재 연습→다음 목표→가족과 5분 야구→근거 기록 확인
완료 조건 / 결과
기록에 없는 내용 생성 금지. 근거 부족 시 '코치 확인 필요'.
12

리포트 편집 및 확정

AI 초안을 코치가 검토·수정하고 최종 리포트를 확정한다.

AI 초안→코치 수정→Before/After 선택→코치 한마디→미리보기→리포트 확정→PDF/이미지 출력
완료 조건 / 결과
상태: Draft → Approved. AI가 자동 발행하지 않음.
13

다음 달 목표 연결

리포트의 다음 목표를 다음 수업의 현재 목표로 연결한다.

확정 리포트→다음 목표 확인→다음 달 목표로 등록→Player Detail 반영→다음 수업에서 목표 노출
완료 조건 / 결과
기록 → 리포트 → 목표 → 다음 수업의 성장 루프 완성.

4. 예외 처리 Flow

상황처리 원칙
선수 결석결석 처리하고 관찰 기록 작성을 요구하지 않는다.
수업 중 기록하지 못함미작성 상태를 유지하고 Dashboard에서 후속 업무로 표시한다.
관찰하지 않은 기술임의 값을 입력하지 않고 비워둔다.
Skill 변화 없음기존 단계를 유지한다.
같은 기술을 여러 번 관찰복수 Observation을 허용한다.
영상이 없음영상 없이도 기록 및 리포트 생성을 허용한다.
AI 근거 부족'코치 확인 필요'로 표시한다.
AI 초안 오류코치가 수정할 수 있으며 자동 발행하지 않는다.
리포트 작성 중 종료Draft 상태로 저장한다.
선수 클래스 변경기존 클래스의 과거 기록은 유지한다.
선수 퇴원데이터 삭제보다 비활성화를 기본 정책으로 한다.

5. 핵심 데이터 관계

Goal → Class → Observation → Skill / Media → Monthly Report → Next Goal ↺ PDS의 핵심은 회원 관리가 아니라 선수의 목표와 실제 수업 데이터를 계속 연결하는 성장 관리 루프다.

6. 다음 설계 산출물

화면 명세서 + Low-Fidelity Wireframe을 작성한다. Dashboard, Players, Player Detail, Classes, Class Log, Skill Ladder, Monthly Report 각 화면의 정보 구조, 입력 요소, 버튼, 이동 경로, 모바일 상태를 확정한 뒤 DB ERD 설계로 진행한다.
