Classes 화면 명세서 v0.1

반복 운영되는 클래스와 특정 날짜에 실제 진행되는 Class Session을 분리하여 선수 소속, 일정, 출결, 수업 시작, 과거 수업 이력을 관리하는 화면.

1. 가장 중요한 개념

Class

강남 토요일 A반
매주 토요일 10:00
정원 10명

Class Session

특정 날짜의 실제 수업

2026-09-22 10:00
출석 8 · 결석 2
상태 completed

Class ≠ Class Session · 클래스 일정이나 소속이 바뀌어도 과거 실제 수업 기록은 그대로 남아야 한다.

2. 핵심 Flow

Classes→Class Detail→Session→수업 시작→Class Log

Class→Membership→현재 선수

Session→Attendance→present 선수→기록 대상

3. 화면 범위

  1. Class List
  2. Class Detail
  3. 현재 Roster
  4. 다음/오늘 Session
  5. Session History
  6. 출결
  7. Class Create/Edit

복잡한 월간 캘린더, 예약, 결제, 보강 관리는 MVP 범위가 아니다.

6. 핵심 데이터 관계

Class1:NClass Schedule

Class1:NMembershipN:1Player

Class1:NClass Session1:NAttendance

Class Session1:NObservation / Class Log
Session Snapshot 원칙 · 현재 Membership만으로 과거 참가자를 다시 계산하지 않는다. 과거 Session의 Attendance가 당시의 실제 참가 사실을 보존한다.

7. Session 상태

scheduled 예정

in_progress 진행 중

completed 종료

cancelled 취소

ACT-CLASS-001 수업 시작 시 기존 Session을 먼저 확인하여 중복 생성을 막는다.

8. 출결 상태

expected 예정

present 출석

absent 결석

결석 = 기록 대상 제외
결석 선수에게 Class Log 완료를 요구하지 않는다.

9. 기록 완료율

완료율의 기준은 현재 클래스 정원이 아니라 해당 Session의 출석 선수다.

항목예시
현재 Class 선수10명
Session 예정9명
출석8명
결석1명
기록 완료6 / 8

선수별 “기록 완료”의 정확한 정의는 Round 5 Class Log에서 확정한다.

13. Mobile UX

  • 오늘/진행 중 Session 우선 노출
  • 수업 시작 CTA 최소 44px 권장
  • Roster는 일부 미리보기 + 전체 보기 가능
  • 최근 Session을 과도하게 펼치지 않음
  • 페이지 전체 가로 스크롤 금지

17. Round 4 결정사항

Classes = “누가 언제 수업하는가”
Round 5 Class Log는 “그 수업에서 무엇을 관찰했는가”를 담당한다.
  • Class / Class Session 분리
  • Attendance는 Session 단위
  • Membership과 과거 참가 Snapshot 분리
  • 복수 Class 소속 허용
  • 기록 완료율은 present 기준
  • 과거 History 소급 변경 금지
  • 예약·결제·보강은 MVP 제외
