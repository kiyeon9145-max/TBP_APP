1. 화면의 역할

Player Detail은 단순 선수 프로필이 아니라 “이 선수가 지금 어디에 있고, 무엇을 연습하고 있으며, 어떻게 변해왔는가”를 확인하는 화면이다.

핵심 질문
현재 목표는? → Skill은 어디까지 왔나? → 최근 수업에서 무엇이 관찰됐나? → 영상 근거는? → 지난 리포트와 다음 목표는?

Player Detail이 PDS의 데이터 허브가 되고, Class Log·Skill Ladder·Media·Monthly Report는 이 선수 데이터를 중심으로 연결된다.

2. 기본 구조

  1. Player Header

6. Current Goal 정책

대표 Current Goal은 한 시점에 1개를 기본으로 한다.

새 Goal을 설정해도 기존 Goal을 삭제하지 않고 Goal History에 보존한다.

current achieved replaced cancelled

Monthly Report의 “다음 달 목표 1개”가 다음 달 Current Goal로 연결되는 구조다.

7. Skill 정책

받기 · 던지기 · 치기 · 주루 각각 현재 Level을 표시한다.

평가하지 않은 영역은 미평가로 표시한다.

자동 승급 금지
Observation이나 AI가 단계를 추천할 수는 있지만 최종 변경은 코치가 승인한다.

Level History는 절대 덮어쓰지 않는다.

9. Media & Report

영상

Thumbnail + 날짜 + Skill + 타입/태그.

최소 연결: player_id / recorded_at / skill_area / file_url

Before / After 태그를 수동으로 붙일 수 있는 구조를 고려한다.

Report

최신 월 우선으로 History 표시.

Draft → 편집　Approved → 보기

각 카드에는 기준 월과 다음 Goal을 요약한다.

11. Empty State

Goal 없음 · 현재 목표가 설정되지 않았습니다.

Skill 없음 · 미평가

Observation 없음 · 아직 수업 기록이 없습니다.

Media 없음 · 아직 등록된 영상이나 사진이 없습니다.

Report 없음 · 아직 생성된 월간 리포트가 없습니다.

12. 상태 변경

active → inactive

확인 문구: “이 선수를 비활성화하시겠습니까? 기존 수업 기록, Skill, 영상, 리포트는 유지됩니다.”

재활성화 가능

MVP에서 영구 삭제는 기본 제공하지 않는다.

17. Round 3 결정사항

Player Detail = 선수 성장 기록 허브
현재 Goal → Skill → 실제 Observation → Media → Report → 다음 Goal을 한 선수 안에서 연결한다.
  • 탭: Overview / 수업기록 / Skill / 영상 / Report
  • 대표 Current Goal 1개
  • Goal·Skill·Class Membership History 보존
  • AI 자동 평가/승급 금지
  • inactive는 삭제가 아님
  • 세부 기록 UX는 Round 5, Skill 기준은 Round 6, Report 작성은 Round 7에서 확정
