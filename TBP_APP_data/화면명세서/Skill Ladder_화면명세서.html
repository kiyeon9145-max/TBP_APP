Skill Ladder 화면 명세서 v0.1

받기·던지기·치기·주루를 숫자 점수가 아닌 관찰 가능한 행동 단계로 관리하고, 실제 수업 Observation을 근거로 코치가 현재 Level을 판단·승인하는 성장 기준 화면.

SCR-SKILL-LADDERP0 · COREBehavior BasedHistory FirstCoach Approved

1. Skill Ladder의 역할

Class Log→Observation→근거 확인→코치 판단→Level 변경→History
Skill Ladder는 선수 평가 점수표가 아니다.
현재 어떤 행동을 할 수 있는지, 이전과 무엇이 달라졌는지를 일관된 기준으로 기록하는 장치다.

2. 설계 원칙

  • 나이가 아닌 실제 수행 수준
  • 점수가 아닌 행동 문장
  • 미평가 허용
  • 자동 승급 금지
  • 코치 최종 승인
  • 승급/하향/건너뛰기 허용
  • 모든 변경 History 보존

3. 하지 않는 것

  • 선수 간 Ranking
  • 종합 점수
  • 평균/별점
  • 나이별 강제 Level
  • AI 자동 평가
  • 성공 횟수 기반 자동 승급

v0.1 기준은 확정 교과서가 아니다.
실제 수업 데이터를 쌓은 뒤 행동 문구와 단계 간 간격을 수정할 수 있도록 설계한다.

7. 미평가 ≠ Level 1

선수를 처음 등록했다고 자동으로 Level 1을 주지 않는다.

미평가
아직 코치가 해당 Skill을 충분히 관찰하지 않은 상태.

DATA-SKILL-009 `unassessed / 1 / 2 / 3 / 4` 지원.

8. 나이 ≠ Skill Level

경험 많은 6세가 Level 4일 수 있고 처음 시작한 10세가 Level 1일 수도 있다.

학년/연령은 Context
Skill Level을 결정하는 자동 규칙으로 사용하지 않는다.

9. Observation은 “근거”

날짜관찰정량
9/08정면 공 포구3/5
9/15정면 공 포구4/5
9/22정면 공을 끝까지 보고 잡음5/5
Observation≠자동 승급 공식
최근 3개 Observation은 코치의 판단을 돕지만, 5/5 = 자동 Level 3 같은 규칙은 만들지 않는다.

11. 승급만 있는 구조가 아니다

승급 · L2 → L3

하향 · L3 → L2

건너뛰기 · 미평가 → L3 / L1 → L3

하향은 벌점이 아니다. 현재 관찰 기준에 맞게 상태를 조정하는 것이다.

12. History First

현재 Level만 저장하고 이전 값을 덮어쓰지 않는다.

History 최소 정보:

  • previous_level / new_level
  • changed_at / changed_by
  • reason
  • evidence Observation

이를 통해 월 시작/종료 시점의 Skill을 재현할 수 있다.

13. Monthly Report 연결

월 시작 Level→월간 Observation→월 종료 Level→부모용 변화 설명
예시
받기 · Level 2 → Level 3

“9월 22일에는 정면으로 오는 공을 5번 중 5번 잡았습니다.”

Round 7에서는 Level 숫자만 보여주는 것이 아니라 실제 Observation과 Media를 함께 사용한다.

14. Starter / Basic / Advanced는 보류

향후에는 Starter Basic Advanced 아래 각각 여러 단계를 둘 수 있다.

MVP에서는 4단계만 사용.
초기부터 12단계 체계를 만들지 않는다. 실제 선수 데이터를 쌓은 뒤 어떤 단계가 필요한지 결정한다.
