## 1. 화면 목적

Dashboard는 로그인 후 가장 먼저 진입하는 **코치 업무 홈 화면**이다.

이 화면의 목적은 통계 분석이 아니라 코치가 접속 즉시 아래 네 가지를 파악하고 행동하게 하는 것이다.

1. 오늘 어떤 수업이 있는가?
2. 지금 시작하거나 이어서 기록해야 할 수업은 무엇인가?
3. 작성하지 못한 선수 기록이 있는가?
4. 이번 달 월간 리포트 작업은 얼마나 남았는가?

### 핵심 원칙

- 오늘 해야 할 업무를 화면 최상단에 둔다.
- 수업 시작까지 가능한 탭 수를 최소화한다.
- 미완료 업무는 숨기지 않고 명확하게 노출한다.
- 분석 차트/매출/복잡한 통계는 MVP Dashboard에 넣지 않는다.
- 모바일에서 한 손으로 주요 액션을 수행할 수 있어야 한다.

## 2. 진입 / 이탈 경로

### 진입

- 로그인 성공 → Dashboard
- 앱/웹 재접속 → 인증 상태가 유효하면 Dashboard
- 다른 주요 화면의 Home/Dashboard 메뉴 → Dashboard

### 이탈

- 오늘 수업 카드 선택 → Classes 또는 해당 Class Session
- `수업 시작` → Class Log
- `기록 계속하기` → 해당 Class Log
- `미작성 기록` → 미작성 기록 대상 목록 또는 Class Log
- `월간 리포트` → Monthly Report
- `선수 등록` → Player Create
- 하단/사이드 내비게이션 → Players / Classes / Reports 등

> 연결 화면의 상세 UI는 해당 라운드에서 정의한다.

## 3. 핵심 사용자 시나리오

### Scenario A — 수업 시작 전

1. 코치가 로그인한다.
2. Dashboard에서 오늘 수업을 확인한다.
3. 가장 가까운 수업의 시간, 클래스명, 예정 선수 수를 확인한다.
4. `수업 시작`을 누른다.
5. Class Log로 이동한다.

### Scenario B — 수업 중/직후 기록 재개

1. Dashboard에 진행 중인 수업이 표시된다.
2. `기록 계속하기`를 누른다.
3. 기존 Class Session을 새로 생성하지 않고 재사용한다.
4. Class Log에서 미작성 선수 기록을 이어간다.

### Scenario C — 저녁 기록 보완

1. Dashboard의 `미작성 기록` 카드를 확인한다.
2. 미작성 선수 수와 관련 수업을 확인한다.
3. 대상 수업으로 이동한다.
4. 기록을 완료한다.
5. Dashboard의 미작성 수가 갱신된다.

### Scenario D — 월말 리포트 작업

1. Dashboard에서 이번 달 리포트 진행률을 확인한다.
2. `리포트 작성하기`를 선택한다.
3. Monthly Report 화면으로 이동한다.

## 4. 정보 구조 우선순위

Dashboard는 아래 순서로 구성한다.

1. Header / 오늘 날짜 / 코치 인사
2. 현재 또는 다음 수업 강조 영역
3. 오늘 수업 목록
4. 해야 할 기록 — 미작성 기록
5. 이번 달 Monthly Report 진행 상황
6. 빠른 실행 — 선수 등록 등
7. Global Navigation

### SCR-DASH-001

시스템은 Dashboard 상단에 현재 날짜를 표시해야 한다.

### SCR-DASH-002

시스템은 오늘 예정된 수업을 시간순으로 표시해야 한다.

### SCR-DASH-003

현재 진행 중인 수업이 있다면 예정 수업보다 우선하여 강조해야 한다.

### SCR-DASH-004

시스템은 미작성 기록의 총 개수를 Dashboard에서 확인할 수 있어야 한다.

### SCR-DASH-005

시스템은 현재 월의 Monthly Report 완료/대상 수를 표시해야 한다.

## 6. 컴포넌트 명세

### CMP-DASH-001 — Header

표시:
- PDS 서비스명 또는 로고
- 현재 날짜
- 코치 이름
- 프로필 진입 버튼

MVP에서는 알림센터를 필수로 구현하지 않는다.

### CMP-DASH-002 — Primary Class Card

목적:
- 현재 진행 중인 수업 또는 가장 가까운 다음 수업을 가장 강하게 노출한다.

표시:
- 상태: `진행 중` / `다음 수업`
- 시작 시간
- 클래스명
- 예정 또는 출석 선수 수
- 기록 진행률(진행 중일 때)

Action:
- 예정 → `수업 시작`
- 진행 중 → `기록 계속하기`

### CMP-DASH-003 — Today Class List

각 카드 표시:
- 시작 시간
- 클래스명
- 선수 수
- 상태
- 이동 아이콘

상태:
- 예정
- 진행 중
- 종료
- 취소

정렬:
- 시작 시간 오름차순

### CMP-DASH-004 — Incomplete Log Card

표시:
- 미작성 선수 총 수
- 수업별 미작성 수 요약
- `이어 작성` Action

미작성 0명일 경우:
- 성공 상태 문구 표시
- 예: `오늘 기록을 모두 작성했어요.`

### CMP-DASH-005 — Monthly Report Progress

표시:
- 기준 월
- 완료 리포트 수
- 대상 선수 수
- 진행률
- Progress Bar
- `작성하기` Action

진행률 계산:
`Approved Report 수 / 해당 월 리포트 대상 선수 수`

Draft는 완료에 포함하지 않는다.

### CMP-DASH-006 — Quick Action

MVP 필수:
- `+ 선수 등록`

향후:
- 클래스 추가
- 영상 추가
- 빠른 메모

### CMP-DASH-007 — Global Navigation

Mobile MVP 권장:
- 홈
- 선수
- 수업
- 리포트

Skill Ladder는 독립 하단 메뉴보다 Player/관리 영역에서 진입하는 방식을 우선 검토한다.

## 7. 주요 액션 명세

### ACT-DASH-001 — 수업 시작

조건:
- 수업 상태가 `scheduled`
- 동일 클래스/시간에 활성 Session이 없음

동작:
1. 버튼 클릭
2. Class Session 생성 또는 시작 처리
3. 상태를 `in_progress`로 변경
4. Class Log로 이동

중복 클릭 시 중복 Session을 생성하면 안 된다.

### ACT-DASH-002 — 기록 계속하기

조건:
- `in_progress` Class Session 존재

동작:
- 기존 Session ID를 사용하여 Class Log로 이동한다.

### ACT-DASH-003 — 미작성 기록 열기

동작:
- 미작성 Observation/선수가 존재하는 Session 목록 또는 가장 관련 있는 기록 화면으로 이동한다.

### ACT-DASH-004 — Monthly Report 열기

동작:
- 현재 월을 기본 필터로 Monthly Report 화면에 진입한다.

### ACT-DASH-005 — 선수 등록

동작:
- 신규 선수 등록 Flow로 이동한다.

## 8. 상태 정의

### Class 상태

- `scheduled`: 예정
- `in_progress`: 진행 중
- `completed`: 종료
- `cancelled`: 취소

### Log 상태

- `not_started`: 기록 없음
- `partial`: 일부 선수만 기록
- `complete`: 필요한 기록 완료

### Report 상태

- `not_started`
- `draft`
- `approved`

Dashboard의 리포트 완료 수에는 `approved`만 포함한다.

## 9. 빈 상태 / 예외 / 에러 처리

### STATE-DASH-001 — 오늘 수업 없음

표시:
`오늘 예정된 수업이 없습니다.`

보조:
- 선수 관리 바로가기 제공 가능
- 가짜 수업 데이터를 만들지 않는다.

### STATE-DASH-002 — 미작성 기록 없음

표시:
`오늘 기록을 모두 작성했어요.`

CTA는 숨기거나 비활성화한다.

### STATE-DASH-003 — 리포트 대상 없음

표시:
`이번 달 리포트 대상 선수가 없습니다.`

0/0 진행률을 0% 또는 100%로 오해하게 표시하지 않는다.

### ERR-DASH-001 — Dashboard 데이터 로드 실패

표시:
`데이터를 불러오지 못했습니다.`

Action:
`다시 시도`

### ERR-DASH-002 — 수업 시작 실패

- 오류 메시지를 표시한다.
- Class Session 생성 여부를 재확인한다.
- 사용자가 버튼을 여러 번 눌러 중복 Session을 만들지 않도록 한다.

## 14. Acceptance Criteria

### AC-DASH-001
Given 코치가 로그인했고 오늘 수업이 존재할 때,  
When Dashboard가 열린다면,  
Then 오늘 수업은 시작 시간순으로 표시되어야 한다.

### AC-DASH-002
Given 진행 중인 Class Session이 존재할 때,  
When Dashboard가 열린다면,  
Then 해당 Session은 가장 우선적인 수업 카드로 표시되고 `기록 계속하기`를 제공해야 한다.

### AC-DASH-003
Given 다음 예정 수업이 있고 진행 중 Session이 없을 때,  
When Dashboard가 열린다면,  
Then 가장 가까운 예정 수업에 `수업 시작` Action을 제공해야 한다.

### AC-DASH-004
Given `수업 시작`을 한 번 실행했을 때,  
When 사용자가 버튼을 반복 클릭하더라도,  
Then 동일 수업의 Class Session이 중복 생성되어서는 안 된다.

### AC-DASH-005
Given 출석 선수 중 기록이 완료되지 않은 선수가 있을 때,  
When Dashboard를 조회하면,  
Then 미작성 선수 수를 확인할 수 있어야 한다.

### AC-DASH-006
Given 미작성 선수가 0명일 때,  
When Dashboard를 조회하면,  
Then `오늘 기록을 모두 작성했어요.` 상태를 표시해야 한다.

### AC-DASH-007
Given 현재 월 리포트 대상이 20명이고 Approved가 16명일 때,  
When Dashboard를 조회하면,  
Then `16 / 20 완료`와 80% 진행 상태를 표시해야 한다.

### AC-DASH-008
Given Report 상태가 Draft일 때,  
When 완료 수를 계산하면,  
Then Draft는 완료 수에 포함되어서는 안 된다.

### AC-DASH-009
Given 오늘 예정된 수업이 없을 때,  
When Dashboard를 조회하면,  
Then 오류가 아닌 정상 Empty State를 표시해야 한다.

### AC-DASH-010
Given 모바일 환경일 때,  
When 사용자가 Dashboard를 사용할 때,  
Then 가로 스크롤 없이 주요 정보와 CTA를 사용할 수 있어야 한다.

- Class Session

Round 5 `Class Log`에서 상세 정의:
- 수업 시작 후 실제 기록 UI
- 선수별 기록 완료 판단 기준
- 출결 입력 상세

Round 7 `Monthly Report`에서 상세 정의:
- 리포트 대상 선수 기준
- Draft/Approved 상세
- AI 초안 생성

Dashboard에서는 위 화면의 상세 정책을 중복 정의하지 않는다.

## 16. Round 1 결정사항 요약

- Dashboard의 본질은 `통계`가 아니라 `오늘의 업무 홈`이다.
- 최우선 정보는 현재 진행 중 수업이며, 없으면 가장 가까운 다음 수업이다.
- 수업 기록 누락을 Dashboard에서 반드시 다시 노출한다.
- Monthly Report는 Approved 기준으로 진행률을 계산한다.
- MVP Quick Action은 `선수 등록`부터 시작한다.
- Mobile First를 기본으로 한다.
