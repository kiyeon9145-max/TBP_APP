# PDS Round 7 — Monthly Report 화면 명세서 v0.1

- 문서 ID: `SCR-MONTHLY-REPORT`
- 제품: PDS (Player Development System)
- 화면: Monthly Report
- 버전: v0.1
- 우선순위: P0 / Core Output
- 주요 사용자: 코치
- 최종 독자: 보호자
- 설계 기준: Mobile First / A4 1 Page / Evidence Based / Coach Approved
- 상위 문서: PDS 요구사항 명세서 v0.1 / PDS User Flow v0.1 / Round 1~6 화면 명세서

---

## 1. 화면 목적

Monthly Report는 한 달 동안 누적된 선수의 수업 기록을 보호자가 빠르게 이해할 수 있는 **1페이지 성장 리포트**로 변환하는 화면이다.

입력 데이터:

```text
Class Log Observation
+ Skill History
+ Media
+ Current / Previous Goal
+ Class Attendance Context
```

출력:

```text
이번 달 무엇이 달라졌는가
+ 실제 근거
+ 지금 무엇을 연습하는가
+ 다음 달 무엇을 목표로 하는가
```

### 보호자가 10초 안에 확인해야 할 3가지

1. **우리 아이가 무엇이 달라졌나?**
2. **코치가 우리 아이를 구체적으로 보고 있나?**
3. **다음에는 무엇을 연습하나?**

---

## 2. 핵심 원칙

- A4 1페이지를 기본으로 한다.
- 긴 수업일지 전체를 부모에게 보여주지 않는다.
- 추상적 칭찬보다 실제 행동 변화가 우선이다.
- Skill Level은 행동 문장과 함께 보여준다.
- Before / After는 실제 Media가 있을 때만 사용한다.
- 없는 사실, 횟수, 변화는 생성하지 않는다.
- 다음 달 목표는 **대표 목표 1개**로 제한한다.
- AI는 초안 작성자이고 코치가 최종 편집·승인한다.
- 승인 전 Draft는 부모 전달용 최종본으로 취급하지 않는다.
- Report는 끝이 아니라 다음 달 Goal로 다시 연결된다.

## 3. Report 생성 Flow

```text
월간 리포트 목록
→ 선수 선택
→ 월간 데이터 자동 수집
→ AI 초안 생성 또는 직접 작성
→ 코치 검토
→ Before / After Media 선택
→ 문구 수정
→ 다음 달 목표 1개 확정
→ 코치 한마디
→ Preview
→ 승인
→ PDF / 이미지 출력
→ 다음 달 Goal 연결
```

## 7. Report 상태

### `not_started`
아직 Report가 없음.

### `draft`
생성/편집 중.

### `approved`
코치가 최종 승인.

### 규칙

Dashboard의 월간 리포트 완료율은 `approved`만 완료로 계산한다.

예:
- 대상 20명
- approved 16명
- draft 2명
- not_started 2명

→ `16 / 20 · 80%`

## 8. Report 대상 선수

MVP 기본 정책:
해당 월에 `active` 상태이고 리포트 대상인 선수.

실제 운영에서는 중도 등록/퇴원 등 예외가 있으므로 `report_eligible` 개념을 둘 수 있다.

### DATA-REPORT-001

0명의 대상자가 있는 경우:
`이번 달 리포트 대상 선수가 없습니다.`

0/0을 0% 또는 100%로 오해하게 표시하지 않는다.

## 13. Before / After

### CMP-REPORT-001

목적:
보호자가 시각적으로 변화를 빠르게 확인.

구성:
- Before 이미지 1개
- After 이미지 1개
- 날짜
- Skill tag

### 원칙

- 가능한 한 같은 Skill
- 가능한 한 비슷한 각도
- 실제 Media만 사용
- Media가 없으면 섹션을 억지로 채우지 않음

### STATE-REPORT-001

Before / After가 충분하지 않으면:
- 사진 1장만 사용
- 또는 해당 섹션 숨김

AI 생성 이미지로 대체하지 않는다.

## 14. Skill 변화

### CMP-REPORT-002

4개 Skill:
- 받기
- 던지기
- 치기
- 주루

표시 예:

```text
받기     Level 2 → Level 3
던지기   Level 2 → Level 3
치기     Level 3 유지
주루     Level 2 유지
```

### 부모용 보조 문구

Level 숫자만 보여주지 않고 현재 행동 기준을 짧게 표시할 수 있다.

예:
`받기 L3 · 정면으로 오는 공을 잡아요`

### DATA-REPORT-004

변화가 없는데 상승한 것처럼 표현하지 않는다.

---

## 15. 이번 달 발견

### CMP-REPORT-003

이번 달 가장 의미 있는 변화/장면 1~2개.

### 좋은 예

`9월 22일에는 정면으로 오는 공을 5번 중 5번 잡았습니다. 월 초에는 글러브를 공 쪽으로 가져가는 단계였다면, 지금은 정면 공을 직접 잡는 장면이 반복해서 나타나고 있습니다.`

### 피할 예

- 많이 발전했습니다.
- 정말 열심히 했습니다.
- 집중력이 훌륭합니다.
- 앞으로가 기대됩니다.

### 원칙

- 가능하면 날짜
- 실제 행동
- 횟수가 존재할 때만 횟수
- 원본 Observation으로 추적 가능

## 16. 지금 연습하고 있어요

### CMP-REPORT-004

기존 표현:
`아직 안 되는 것`

부모용 최종 표현:
**`지금 연습하고 있어요`**

목적:
현재 과제를 숨기지 않으면서 부정적 낙인처럼 표현하지 않기 위함.

예:
`정면 공은 안정적으로 잡기 시작했고, 지금은 좌우로 이동한 뒤 공을 잡는 연습을 하고 있습니다.`

## 17. 다음 달 목표

### CMP-REPORT-005

**대표 목표 1개만 설정.**

예:
`좌우 이동 후 포구`

### 규칙

- 측정/관찰 가능한 행동
- 너무 많은 목표 금지
- 다음 달 수업에서 코치가 바로 확인 가능한 내용

### ACT-REPORT-001

Report 승인 시 선택한 `다음 달 목표`를 Player의 Current Goal로 연결할 수 있어야 한다.

확인:
`이 목표를 다음 달 현재 목표로 설정할까요?`

## 18. 가족과 5분 야구

### CMP-REPORT-006

집에서 가족과 짧게 할 수 있는 연습 1개.

원칙:
- 5분 내외
- 별도 전문 장비 최소화
- 안전
- 부모가 이해 가능한 설명
- 해당 선수의 다음 Goal과 연결

예:
`부드러운 공으로 2~3m 거리에서 좌우로 한 걸음씩 움직여 공을 받아보세요. 정확한 자세보다 공을 끝까지 보고 이동해서 잡는 데 집중합니다.`

## 19. 코치 한마디

### CMP-REPORT-007

코치가 직접 남기는 짧은 메시지.

목적:
자동 생성 문서가 아니라 실제 코치가 선수를 보고 있다는 느낌을 전달.

권장:
2~4문장 이하.

AI 초안을 사용할 수 있지만 최종 내용은 코치가 확인한다.

## 20. Evidence Drawer

### CMP-REPORT-008

Editor에서 각 AI/요약 문구의 원본 근거를 확인할 수 있어야 한다.

예:

```text
근거 기록 3개

9/08 · 받기
정면 포구 3/5

9/15 · 받기
정면 포구 4/5

9/22 · 받기
정면 포구 5/5
```

### 목적

- AI hallucination 방지
- 코치 검수 속도 향상
- 문구 수정 근거 확보

Evidence는 최종 부모용 PDF에 반드시 노출할 필요는 없다.

## 21. AI 초안 생성

### ACT-REPORT-002 — Generate AI Draft

입력:
- 해당 월 Observation
- Skill History
- Goal
- Media metadata

출력 후보:
- 이번 달 발견
- 지금 연습하고 있어요
- 다음 달 목표 후보
- 가족과 5분 야구
- 코치 한마디 초안

### AI 금지 사항

- 없는 사실 생성
- 없는 날짜 생성
- 없는 성공/시도 횟수 생성
- Observation 없는 Skill 향상 주장
- 자동 Report 승인
- 자동 부모 전송

### 표현 제한

가능하면 아래와 같은 빈 칭찬 표현을 단독 근거로 사용하지 않는다.

- 향상
- 노력
- 성실
- 열심히
- 최선
- 훌륭
- 기대됩니다
- 발전
- 꾸준히

행동 사실로 대체한다.

## 25. 승인

### ACT-REPORT-005 — Approve Report

승인 전 Validation:

- 선수 / 월
- 핵심 요약
- 다음 달 목표
- 코치 확인
- 출력 가능한 상태

Before/After는 필수가 아니다.

### 승인 결과

`draft → approved`

저장:
- approved_at
- approved_by

### 정책

승인된 Report는 해당 시점의 내용 Snapshot을 보존한다.

원본 Observation이 나중에 수정되어도 이미 전달한 Report가 조용히 바뀌지 않도록 한다.

---

## 26. 승인 후 수정

실제 운영상 오타 수정이 필요할 수 있으므로 수정은 허용한다.

권장 정책:

```text
Approved v1
→ 수정
→ Draft revision
→ 재승인
→ Approved v2
```

MVP에서는 단순 재편집 + 재승인으로 시작할 수 있으나 `updated_at`을 남긴다.

향후 Version History 확장 가능.

## 34. Acceptance Criteria

### AC-REPORT-001
Given 특정 월 Report List에 진입했을 때,  
Then 대상 선수별 not_started / draft / approved 상태를 확인할 수 있어야 한다.

### AC-REPORT-002
Given 대상 20명 중 approved 16명일 때,  
Then 완료율은 `16/20 · 80%`로 표시되어야 한다.

### AC-REPORT-003
Given draft Report가 존재할 때,  
Then 완료 수에 포함하면 안 된다.

### AC-REPORT-004
Given Report를 새로 생성할 때,  
Then 해당 월 Observation / Skill History / Media / Goal 데이터를 불러올 수 있어야 한다.

### AC-REPORT-005
Given Skill Level이 월 중 변경되었을 때,  
Then 월 시작/종료 상태를 재현하여 변화로 표시할 수 있어야 한다.

### AC-REPORT-006
Given Skill 변화가 없을 때,  
Then `유지`로 표시할 수 있어야 하며 임의의 상승을 생성하면 안 된다.

### AC-REPORT-007
Given 횟수가 기록되지 않은 Observation만 있을 때,  
Then AI가 임의의 성공/시도 횟수를 생성하면 안 된다.

### AC-REPORT-008
Given Before/After Media가 없을 때,  
Then Report 작성과 승인이 가능해야 한다.

### AC-REPORT-009
Given AI Draft 문구가 생성되었을 때,  
Then 코치는 관련 Evidence Observation을 확인할 수 있어야 한다.

### AC-REPORT-010
Given 근거가 부족할 때,  
Then 시스템은 사실을 생성하지 않고 코치 확인 상태를 표시해야 한다.

### AC-REPORT-011
Given Report 작성 중일 때,  
Then Draft로 저장하고 다시 이어서 편집할 수 있어야 한다.

### AC-REPORT-012
Given Preview를 열었을 때,  
Then A4 1페이지 최종 출력 형태를 확인할 수 있어야 한다.

### AC-REPORT-013
Given Report가 A4 1페이지를 초과할 때,  
Then 사용자에게 경고를 표시해야 한다.

### AC-REPORT-014
Given 코치가 Report를 승인했을 때,  
Then status가 approved로 변경되고 approved_at / approved_by를 저장해야 한다.

### AC-REPORT-015
Given Report가 approved 되었을 때,  
Then 승인 시점 내용 Snapshot이 보존되어야 한다.

### AC-REPORT-016
Given Approved Report의 다음 달 목표가 존재할 때,  
Then 코치는 이를 Player Current Goal로 연결할 수 있어야 한다.

### AC-REPORT-017
Given PDF/이미지 생성이 실패했을 때,  
Then approved Report 데이터 자체가 취소되거나 삭제되어서는 안 된다.

### AC-REPORT-018
Given 모바일 환경일 때,  
Then 섹션별 편집과 Preview를 가로 페이지 스크롤 없이 사용할 수 있어야 한다.

### AC-REPORT-019
Given AI Draft가 생성되었을 때,  
Then 코치 승인 없이 부모용 최종 Report로 자동 전환되어서는 안 된다.

## 36. Round 7 결정사항 요약

- Monthly Report는 PDS의 핵심 부모용 Output이다.
- 부모가 10초 안에 `변화 / 코치의 구체적 관찰 / 다음 목표`를 파악해야 한다.
- A4 1페이지가 기본이다.
- Before/After는 실제 Media가 있을 때만 사용한다.
- Skill은 숫자만이 아니라 행동 기준과 함께 보여준다.
- `아직 안 되는 것` 대신 `지금 연습하고 있어요`를 사용한다.
- 다음 달 목표는 대표 1개만 설정한다.
- 가족과 5분 야구를 다음 Goal과 연결한다.
- AI는 초안만 만들며 Evidence를 함께 보여준다.
- 근거가 부족하면 만들어내지 않는다.
- Draft → Approved 상태를 사용한다.
- Approved Report는 Snapshot을 보존한다.
- PDF/이미지 출력 후 코치가 부모에게 전달한다.
- 승인된 Next Goal은 다음 달 Current Goal로 연결되어 PDS Loop를 완성한다.
