Class Detail 설계 의도

Class Detail은 반복 클래스 자체를 관리하면서 오늘/다음 실제 Session으로 진입하는 허브다. 코치는 이 화면에서 다음 수업, 현재 Roster, 과거 Session의 기록 완료 상태를 확인한 뒤 출석과 Class Log로 이동한다.

01 · Class Summary

클래스명, 반복 일정, 현재 인원/정원, 수업 시간, 최근 수업을 상단에서 확인한다. 이 값은 현재 Class 정보이며 과거 Session 데이터와 구분한다.

02 · Next Session

가장 가까운 예정 Session을 가장 강한 카드로 배치한다. CTA는 수업 시작이며 이미 진행 중인 Session이 있으면 기록 계속하기로 변경한다.

03 · Start Session Transaction

Session 존재 확인→중복 방지→Roster Snapshot→Attendance 생성→in_progress→Class Log

수업 시작은 단순 페이지 이동이 아니라 여러 DB 변경이 연결되는 작업이므로 백엔드 트랜잭션으로 처리한다.

04 · Current Roster

현재 클래스에 소속된 선수 목록이다. 카드에서는 이름과 Current Goal을 보여주고 Player Detail로 이동할 수 있다. MVP에서는 상위 일부만 노출하고 전체 보기로 확장한다.

05 · Roster 변경

현재 Roster에서 선수를 추가·제외해도 이미 생성된 과거 Session의 Attendance/Roster Snapshot에는 영향을 주지 않는다.

06 · Session History

최근 Session은 날짜, 출석 인원, 기록 완료 인원, 상태를 보여준다. 완료율의 분모는 present 선수이며 absent 선수는 제외한다.

07 · Completion

present 선수에게 유효한 Observation이 1개 이상 있으면 해당 선수의 기록을 완료로 본다. 한 선수에게 Observation은 여러 개 생성할 수 있다.

08 · Session Status

scheduled

수업 시작 전

in_progress

출석/기록 진행 중

completed

수업 종료

cancelled

취소된 수업

09 · Class Settings

반복 일정, 정원, 운영 상태 등 현재 Class 설정을 수정한다. 영구 삭제보다는 운영 종료/비활성을 사용해 기존 History를 보존한다.

10 · Sticky CTA

현장에서 한 손으로 빠르게 수업을 시작할 수 있도록 모바일 하단에 48px Primary CTA를 고정한다. 상단 Session 카드 CTA와 동일한 Action이다.

11 · 다음 화면: Class Log

수업 시작→출석 확인→선수 선택→Skill 선택→Observation→저장 & 다음 선수→수업 종료

Class Log가 실제 현장 입력의 핵심 화면이다. 목표는 선수 1명당 약 30초 내 기록이며 모든 Skill을 매 수업마다 강제로 평가하지 않는다.

12 · Design Tokens

Primary #0B2A4A, Active #1546F5, Surface White, Border Gray 200, Card radius 12px, CTA 44–48px를 유지한다.

13 · Navigation

Class Detail은 하위 상세 화면이므로 Global Bottom Navigation 대신 Back + Context Header + Sticky Action을 우선한다.
