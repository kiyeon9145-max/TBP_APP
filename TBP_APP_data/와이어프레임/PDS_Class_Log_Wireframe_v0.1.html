Class Log 설계 의도

PDS의 핵심 입력 화면이다. 목표는 코치가 수업 흐름을 끊지 않고 선수 1명당 약 30초 안에 유효한 Observation을 남기는 것이다. 따라서 필수 입력은 최소화하고, Skill Level 변경이나 복잡한 평가 작업은 이 화면에서 분리한다.

01 · Core Flow

출석 확인→선수 선택→Skill 1개 선택→Observation 작성→선택: 횟수/Media→저장 & 다음 선수

모든 Skill을 매 수업마다 평가하도록 강제하지 않는다. 실제로 관찰한 행동만 기록하는 구조다.

02 · Session Progress

상단에서 출석 인원과 기록 완료 인원을 계속 보여준다. 완료율 분모는 present 선수만 사용하며 absent 선수는 제외한다.

03 · Player Strip

완료 선수는 ✓, 현재 선수는 Blue Outline, 미작성 선수는 Neutral, 결석 선수는 Disabled 형태로 구분한다. 탭하면 즉시 해당 선수 입력 화면으로 이동한다.

04 · Current Goal

코치가 오늘 관찰할 포인트를 바로 떠올릴 수 있도록 선수 이름 아래 Current Goal을 노출한다. Goal은 참고 정보이며 Observation 내용과 반드시 동일할 필요는 없다.

05 · Skill 선택

받기 / 던지기 / 치기 / 주루 4개를 Chip/Segmented 형태로 제공한다. 드롭다운보다 빠르게 선택할 수 있도록 한 화면에 모두 노출한다.

06 · Observation

Observation은 핵심 필수 데이터다. 최소 96px 이상의 Textarea와 자주 사용하는 Quick Phrase를 제공한다. Quick Phrase는 문장을 완성하는 보조 기능이지 자동 평가가 아니다.

07 · Attempts / Successes

횟수는 선택 입력이다. 입력한 경우 successes ≤ attempts를 검증한다. 숫자가 없더라도 Observation 저장은 가능해야 한다.

08 · Multiple Observations

한 선수에게 한 Session에서 Observation을 여러 개 남길 수 있다. 예: 던지기 관찰 1개 + 치기 관찰 1개. 각각 독립 row로 저장한다.

09 · Media

사진·영상은 선택이다. Observation 텍스트를 먼저 저장할 수 있어야 하며 Media 업로드 실패가 관찰 기록 저장 실패로 이어지면 안 된다.

10 · 저장 후 행동

저장 & 다음 선수

Observation 저장 후 다음 미작성 present 선수로 자동 이동.

임시 저장

작성 중 상태를 보존하고 현재 선수에 머무름.

수업 종료

미작성 선수가 있으면 확인 후 종료 가능. 종료 후에도 후속 기록 허용.

11 · Completion Rule

present 선수에게 유효한 Observation 1개 이상이 있으면 해당 선수는 기록 완료다. Skill Level 변경 여부와는 무관하다.

12 · Skill Level 분리

Class Log에서는 Skill Level을 자동 변경하지 않는다. Observation은 Skill 판단의 Evidence가 되고, 실제 Level 변경은 Skill Ladder에서 코치가 승인한다.

13 · Draft / Exit Safety

입력 중 뒤로가기나 선수 이동 시 작성 내용을 보존하거나 이탈 경고를 제공한다. 현장 입력 중 실수로 텍스트가 사라지지 않아야 한다.

14 · Touch UX

Skill, Counter, Save 등 주요 조작 영역은 최소 44×44px. Primary CTA는 48px로 고정하여 한 손 조작을 고려한다.

15 · 데이터 관계

Class Session1 → NAttendance→Player1 → NObservation→Skill / Media

Observation은 Session과 Player에 귀속되고 선택한 Skill Area를 참조한다. 같은 선수·같은 Session에도 여러 Observation이 존재할 수 있도록 설계한다.
