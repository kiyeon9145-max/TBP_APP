Skill Ladder 설계 의도

명세서의 핵심인 Behavior Based / History First를 그대로 적용했다. 선수 간 비교나 점수화가 아니라, 현재 관찰 가능한 행동을 확인하고 Class Log의 Observation을 근거로 코치가 단계를 승인하는 구조다.

01 · 핵심 Flow

Class Log→Observation 누적→근거 확인→코치 판단→Level 변경→History 저장→Monthly Report

02 · Skill Summary

받기·던지기·치기·주루 각각의 Current Level + 행동 기준 + 최근 변경 여부를 보여준다. 카드를 선택하면 해당 Skill Detail로 이동한다.

03 · 행동 문장

“우수/보통/미흡” 같은 추상 평가 대신 “정면으로 오는 공을 잡는다”처럼 코치와 부모 모두 이해할 수 있는 관찰 행동을 사용한다.

04 · Ladder

현재 Level을 Blue로 명확하게 강조한다. 이전 Level은 과거 경로로 표시하지만 게임처럼 반드시 순차 통과해야 하는 구조는 아니다.

05 · 미평가

처음 등록한 선수를 임의로 Level 1로 두지 않는다. 평가하지 않았다면 미평가로 표시하고 CTA는 “초기 단계 설정”으로 변경한다.

06 · Evidence

해당 Skill의 최근 Observation 3개를 우선 노출한다. 성공 횟수는 존재할 때만 표시하며 Evidence는 자동 승급 공식이 아니다.

07 · Level 변경

단계 변경 시 새 Level, 행동 기준, 최근 Evidence, 변경 이유를 확인한 후 저장한다. AI나 횟수만으로 자동 변경하지 않는다.

08 · 하향/건너뛰기

Level 3→2 하향과 미평가→3, Level 1→3 같은 건너뛰기도 허용한다. 실패/벌점 표현 없이 현재 관찰 기준의 조정으로 취급한다.

09 · 변경 이유

명세서 기준 예시는 최근 수업에서 반복 확인 / 초기 평가 / 기준 재평가 / 기타다. 기존 Level 변경 시 이유 입력을 권장한다.

10 · History First

현재 값은 빠른 조회를 위해 별도로 유지할 수 있지만 과거 변경 이력을 덮어쓰면 안 된다. History에는 previous/new level, 변경 시각·코치·이유·메모·Evidence 연결 정보를 보존한다.

11 · 나이는 Context

학년/연령은 참고 정보일 뿐 Skill Level 결정 규칙이 아니다. 실제 수행 행동을 기준으로 판단한다.

12 · 금지 표현

  • 선수 간 순위
  • 종합/평균 점수
  • 별점
  • 나이별 강제 Level
  • 자동 승급
