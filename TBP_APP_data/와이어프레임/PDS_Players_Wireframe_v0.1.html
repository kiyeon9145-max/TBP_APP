Players 설계 의도

Players는 단순 연락처 목록이 아니라 성장 관리 대상 목록이다. 코치가 이름으로 선수를 빠르게 찾고, 카드에서 현재 목표와 최근 기록 상태만 훑은 뒤 Player Detail로 들어가도록 정보량을 제한했다.

01 · Header / 등록

화면 제목과 ＋ 등록을 같은 영역에 둔다. 신규 선수 등록은 핵심 작업이므로 상단에서 즉시 접근하고, 긴 목록 끝에도 동일 목적의 CTA를 한 번 더 제공한다.

02 · Search

MVP 검색 대상은 선수 이름이다. 부분 일치, 앞뒤 공백 제거, 한글 이름 검색을 기준으로 하며 검색 결과가 없으면 별도 Empty State를 보여준다.

03 · Filter

필터는 MVP에서 클래스 / 선수 상태 두 가지로 제한한다. 기본값은 전체 클래스 + 활동 중이다.

04 · Summary / Sort

현재 필터 결과 수를 활동 선수 20명처럼 표시한다. 기본 정렬은 이름순으로 두어 코치가 예측 가능한 위치에서 선수를 찾게 한다.

05 · Player Card 정보 우선순위

선수 이름→학년/연령 · 클래스→현재 목표 1개→최근 기록일→Player Detail

보호자 전화번호, Skill 4개 전체, 긴 코치 메모, 결제 상태, 민감 정보는 목록에서 제외한다. 카드 전체를 탭 가능한 영역으로 취급한다.

06 · Growth Focus

카드에서 가장 중요한 보조 정보는 현재 목표다. 회색 Surface 안에 묶어 시선은 잡되, Primary Action보다 강하지 않게 구성했다.

07 · Inactive Player

선수는 삭제보다 비활성 상태로 관리한다. 비활성으로 전환해도 과거 수업, Skill, Media, Report 데이터는 유지되어야 한다.

상태별 화면

검색 결과

“민준” 검색 시 결과 수와 일치 선수 카드만 표시한다.

검색 결과 없음

“일치하는 선수가 없습니다.” + 검색어 지우기 CTA를 제공한다.

선수 없음

첫 선수 등록을 유도하는 Empty State와 ＋ 선수 등록 CTA를 제공한다.

08 · Design Tokens

  • Primary: #0B2A4A
  • Active: #1546F5
  • Background: #F8FAFC
  • Card radius: 12px
  • Input / CTA: 48px
  • Touch target: 44px+

09 · Global Navigation

Dashboard와 동일한 홈 / 선수 / 수업 / 리포트 구조를 유지하고 현재 화면인 선수만 TBP Blue로 활성 표시한다.

반응형 원칙

360–390px 모바일에서는 1열 카드 리스트를 유지한다. Tablet/Desktop에서는 검색·필터 폭을 확장하고 선수 카드를 2열로 배치할 수 있지만, 이름 → 현재 목표 → 최근 기록의 정보 우선순위는 바꾸지 않는다. 프로필 사진은 선택 요소이며 이미지가 없어도 이니셜 아바타로 완전하게 사용할 수 있어야 한다.
