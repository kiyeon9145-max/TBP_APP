Classes 설계 의도

Classes는 단순 일정표가 아니라 반복 운영되는 Class를 관리하고 실제 Class Session으로 진입하는 화면이다. 오늘 실행해야 할 수업을 먼저 보여주고, 그 아래에서 현재 운영 중인 클래스의 인원과 다음 일정을 빠르게 확인하도록 구성했다.

01 · Class ≠ Class Session

Class는 “강남 토요일 A반”처럼 반복되는 그룹이고, Class Session은 “9월 22일 A반 수업”처럼 실제 날짜에 열린 수업이다. 두 데이터를 분리한다.

02 · 오늘 수업 우선

코치가 앱을 열었을 때 가장 먼저 필요한 것은 오늘 진행할 수업이다. 가장 가까운 예정 Session을 Navy Primary Card로 강조하고 바로 수업 시작할 수 있게 한다.

03 · 수업 시작 Flow

Class 선택→오늘 Session 확인→중복 Session 방지→Roster Snapshot→출석 확인→Class Log

시작 시 현재 클래스 소속 선수를 기준으로 해당 Session의 명단을 snapshot하고 출석 기록을 만든다. 이후 클래스 구성원이 바뀌어도 과거 Session의 선수 명단은 변하지 않아야 한다.

04 · Class Card

목록 카드에는 클래스명 / 요일·시간 / 현재 인원 / 정원 / 다음 수업 / 최근 수업만 노출한다. 출석 상세나 개별 선수 기록은 Class Detail 또는 Session에서 확인한다.

05 · Today State

오늘 수업이 있는 클래스에는 Blue 기반 오늘 상태를 붙여 일반 운영 중 클래스보다 빠르게 식별할 수 있도록 한다.

06 · Session Status

scheduled

예정

in_progress

진행 중

completed

완료

cancelled

취소

07 · 진행 중 우선순위

이미 in_progress Session이 있으면 새 Session을 생성하지 않는다. Primary CTA를 기록 계속하기로 변경하고 기존 session_id를 사용한다.

08 · Class 변경 원칙

요일, 시간, 정원, 현재 멤버를 수정해도 이미 종료된 Session의 사실관계는 수정하지 않는다. 과거 데이터는 Session/Attendance snapshot을 기준으로 유지한다.

09 · Empty State

등록된 클래스가 없으면 “아직 등록된 수업이 없습니다.”와 ＋ 첫 수업 만들기 CTA를 제공한다. 오늘 수업만 없는 경우 전체 클래스 목록은 그대로 유지한다.

10 · 다음 화면 구조

Classes→Class Detail→오늘/다음 Session→출석→Class Log→Session 완료

Class Detail에서는 기본 정보, 현재 선수, 오늘/다음 Session, 최근 Session History, 클래스 수정을 제공한다. 실제 선수별 Observation 입력은 Class Log에서 수행한다.

11 · Design System

Primary #0B2A4A, Active #1546F5, Card radius 12px, CTA 44–48px를 사용해 Dashboard·Players와 동일한 시스템을 유지했다.

12 · Global Navigation

기존과 동일하게 홈 / 선수 / 수업 / 리포트를 유지하며 현재 화면인 수업만 Blue Active 상태로 표시한다.
