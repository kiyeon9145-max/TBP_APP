1. 문서 정의 및 서비스 목적

현재 문서는 초기 요구사항 명세서에 해당한다. 개발자가 바로 구현할 수준의 상세 SRS라기보다, 제품이 해결할 문제와 MVP 기능·범위·운영 원칙을 확정하기 위한 제품 요구사항(PRD) + 기능 요구사항 초안에 가깝다.

핵심 목적
유소년 선수의 수업·기술·영상·성장 과정을 코치가 지속적으로 기록하고, 누적 데이터를 기반으로 선수별 성장 관리와 부모 리포트를 제공한다.

서비스의 기본 성장 루프는 다음과 같다.

수업 → 관찰 → 기록 → 성장 확인 → 다음 목표 설정 → 다음 수업

단순 회원관리 프로그램이 아니라, 코치의 관찰과 선수의 성장 이력을 연결하는 Player Development System을 지향한다.

2. 핵심 사용자 및 권한

MVP Primary User

코치 1명을 기본 사용자로 정의한다. 코치는 로그인 후 선수, 클래스, 수업기록, 기술 단계, 영상/사진, 월간 리포트를 관리한다.

코치 로그인
  ↓
선수 등록 → 클래스 배정 → 수업 진행 → 관찰 기록
  ↓
영상/사진 연결 → Skill Ladder 업데이트
  ↓
월간 리포트 생성 → 코치 검토/수정 → 부모에게 전달

향후 관리자/원장, 다중 코치, 부모, 선수 계정을 확장할 수 있도록 데이터 구조는 확장 가능성을 고려한다.

3. 기능 요구사항

A. 선수 관리

FR-PLAYER-01
코치는 새로운 선수를 등록할 수 있어야 한다.
FR-PLAYER-02
선수의 이름, 생년월일/나이, 학년, 투타, 야구 경험, Skill Level, 등록일, 소속 클래스, 특이사항, 현재 목표를 저장·수정할 수 있어야 한다.
FR-PLAYER-03
선수 상세 화면에서 수업기록, Skill 변화, 미디어, 리포트를 시간순으로 확인할 수 있어야 한다.

B. 클래스 관리

FR-CLASS-01
코치는 클래스를 생성·수정하고 여러 선수를 클래스에 배정할 수 있어야 한다.
FR-CLASS-02
클래스에는 명칭, 요일/시간, 장소, 정원, 소속 선수를 관리할 수 있어야 한다.
FR-CLASS-03
‘오늘 수업 시작’을 통해 해당 클래스의 선수 목록을 한 번에 불러올 수 있어야 한다.

C. 수업 기록

FR-LOG-01
선수별로 날짜, 수업, 기술 영역, 관찰 행동, 시도 횟수, 성공 횟수, 코치 메모, Skill Level을 기록할 수 있어야 한다.
FR-LOG-02
기술 영역은 MVP에서 받기·던지기·치기·주루 4개로 시작한다.
FR-LOG-03
한 선수의 한 수업에 여러 개의 관찰 기록을 남길 수 있어야 한다.
FR-LOG-04
선수 1명 기록 완료 시간을 30초 이내로 만드는 것을 UX 목표로 한다.

D. Skill Ladder

FR-SKILL-01
기술 수준은 점수 대신 관찰 가능한 행동 기반 단계로 관리한다.
FR-SKILL-02
Skill 변경 시 이전 기록을 덮어쓰지 않고 날짜별 변화 이력을 보존해야 한다.
FR-SKILL-03
Starter / Basic / Advanced 등 레벨별 Ladder를 향후 추가할 수 있어야 한다.
예: 받기 Starter — ① 공을 피하거나 눈을 감음 → ② 눈을 뜨고 글러브를 공 쪽으로 댐 → ③ 정면 공을 잡음 → ④ 옆으로 이동하여 잡음

E. 영상·사진 관리

FR-MEDIA-01
선수별 영상과 사진을 업로드 또는 연결할 수 있어야 한다.
FR-MEDIA-02
각 미디어에는 선수, 날짜, 수업, 기술 영역, 태그, 코치 메모를 연결해야 한다.
FR-MEDIA-03
선수 상세 화면에서 기술 영역별로 미디어를 필터링할 수 있어야 한다.
FR-MEDIA-04
향후 Before/After 비교 기능을 지원할 수 있는 구조여야 한다.

F. 월간 성장 리포트

FR-REPORT-01
한 달 동안 누적된 선수 데이터를 바탕으로 부모용 리포트 초안을 생성할 수 있어야 한다.
FR-REPORT-02
리포트에는 이번 달 변화, Skill 변화, 이번 달 발견, 현재 연습 내용, 다음 목표 1개, 가족과 5분 야구, 코치 한마디를 포함한다.
FR-REPORT-03
AI가 생성한 리포트는 반드시 코치가 검토·수정·승인한 후 최종본이 되어야 한다.
FR-REPORT-04
최종 리포트는 모바일 이미지 또는 인쇄 가능한 A4 1장 형태로 출력 가능한 방향을 고려한다.

G. Dashboard

FR-DASH-01
로그인 직후 오늘 수업, 오늘 선수, 미작성 기록, 월간 리포트 진행상태를 확인할 수 있어야 한다.
FR-DASH-02
통계 중심이 아니라 ‘오늘 해야 할 일’을 빠르게 실행하는 업무 대시보드로 설계한다.

5. UX 요구사항

  • Mobile First: 수업 현장에서 스마트폰으로 핵심 기록을 완료할 수 있어야 한다.
  • 30초 기록: 선수 1명의 핵심 기록은 30초 이내를 목표로 한다.
  • 중복 입력 최소화: 클래스·날짜·수업 정보는 가능한 한 자동 상속한다.
  • 선택형 UI 우선: 반복 입력은 텍스트보다 버튼·단계 선택을 우선한다.
  • 객관적 기록: ‘잘함’보다 ‘정면 포구 5회 중 4회’와 같은 관찰 행동을 기록한다.
  • History First: 성장 기록은 덮어쓰지 않고 누적한다.

6. AI 요구사항

AI의 역할은 코치의 판단을 대체하는 평가자가 아니라 기록 정리 및 문서 작성 보조자로 제한한다.

AI-01. 메모/음성 → 구조화 기록

입력: “민준이 오늘 정면 포구 다섯 개 중 네 개 잡았고 공을 끝까지 보기 시작함.”
출력: 받기 / 정면 포구 / 시도 5 / 성공 4 / 공을 끝까지 바라봄

AI-02. 월간 기록 → 리포트 초안

AI는 해당 선수의 실제 저장 기록만 사용해야 하며, 기록에 없는 사실을 생성해서는 안 된다. 정보가 부족하면 ‘코치 확인 필요’ 상태로 표시한다.

필수 승인 흐름: AI 생성 → 코치 검토 → 코치 수정 → 코치 승인 → 최종 리포트

7. 비기능 요구사항

NFR-01
반응형: 모바일과 데스크톱에서 사용할 수 있어야 한다.
NFR-02
개인정보: 미성년자 데이터와 영상은 권한 없는 사용자가 접근할 수 없어야 한다.
NFR-03
데이터 보존: 기록 수정 시 핵심 성장 이력이 의도치 않게 유실되지 않아야 한다.
NFR-04
파일 관리: 영상/사진은 선수 데이터와 연결되어 검색 가능한 상태로 관리한다.
NFR-05
확장성: 향후 다중 코치·부모 계정·출결·예약 기능을 추가할 수 있는 구조를 고려한다.

※ 미성년자 영상·개인정보 수집 및 AI 활용에 필요한 동의 문구와 보존/삭제 정책은 실제 운영 전 별도의 개인정보·운영 정책으로 구체화해야 한다.

8. MVP 범위

IN — MVP 1.0
코치 로그인 · 선수 관리 · 클래스 관리 · 수업 기록 · Skill Ladder · 사진/영상 연결 · 월간 리포트 · AI 기록/리포트 초안
OUT — 후속 버전
부모/선수 로그인 · 수강료 결제 · 예약 · 카카오 자동발송 · 개인레슨 판매 · 복잡한 통계 · AI 영상 자세 분석 · 여러 지점 관리 · 다중 코치 권한 · 출결 자동 알림

9. MVP 성공 기준

지표목표의미

수업 기록률실제 수업의 80% 이상기록 습관 정착
